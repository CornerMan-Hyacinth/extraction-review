# Extraction Review

AI extraction is only useful if people can trust it and fix it quickly. This project is a front-end prototype of that review step: a two-pane interface for checking structured data pulled from financial documents such as capital call notices, fund reports and invoices.

**Live demo:** https://73e2ee93.extraction-review.pages.dev/

## What it does

- Renders the source PDF in the browser with pdf.js
- Lists extracted fields with green, amber and red confidence badges
- Highlights the exact region of the PDF a field was read from when you click it
- Flags low-confidence fields for review, with one-click confirm or inline edit
- Tracks progress in a summary bar (for example, "47/52 fields validated")

## Why I built it

I wanted to explore the UX problem at the heart of document intelligence products: automation handles the bulk of the work, and the interface decides how efficiently people handle the rest. The goal was to make that remaining review fast, traceable and low-friction.

## Technical notes

- Built with React, Next.js (static export), TypeScript, Tailwind and pdf.js
- The default sample document is synthetic and generated by `scripts/generate-pdf.mjs`, which also writes the matching fields and bounding boxes, so highlights line up exactly
- Extraction output for the sample is mocked. In production this would come from an extraction API returning the same shape (value, confidence, page, bounding box)
- Review state is client-side only and there is no backend, so documents never leave the browser

## Running locally

```bash
npm install
node scripts/generate-pdf.mjs   # creates the sample PDF and its fields
npm run dev
```

## Building for deployment

```bash
npm run build
```

This produces a static site in `out/`, which can be hosted on any static host.

## Possible next steps

Keyboard-driven review, an audit trail of confirmations and edits, cross-field validation (such as line items summing to a total), OCR for scanned documents, and multi-document queues.
